## 4. 角色和权限控制实现分析

### 1. 权限控制体系架构

jshERP前端实现了完整的细粒度权限控制体系，采用了多层次的权限控制机制，确保系统安全性。

### 2. 核心实现机制

#### 2.1 路由级别权限控制
- **实现方式**：通过Vue Router的路由守卫（router.beforeEach）实现
- **工作原理**：
  1. 用户登录后，前端从后端获取权限列表
  2. 根据权限列表动态生成可访问的路由配置
  3. 通过 `router.addRoutes` 方法动态添加到路由系统中
  4. 未授权的路由会被过滤掉，用户无法直接访问
- **关键代码**：
  ```javascript
  // permission.js
  router.beforeEach((to, from, next) => {
    if (Vue.ls.get(USER_ID)) {
      if (store.getters.permissionList.length === 0) {
        store.dispatch('GetPermissionList').then(res => {
          const menuData = res;
          // 缓存用户的按钮权限
          store.dispatch('GetUserBtnList').then(res => {
            Vue.ls.set('winBtnStrList', res.data.userBtn, 7 * 24 * 60 * 60 * 1000)
          })
          let constRoutes = [];
          constRoutes = generateIndexRouter(menuData);
          // 添加主界面路由
          store.dispatch('UpdateAppRouter', { constRoutes }).then(() => {
            // 动态添加可访问路由表
            router.addRoutes(store.getters.addRouters)
            const redirect = decodeURIComponent(from.query.redirect || to.path)
            next({ path: redirect })
          })
        })
      } else {
        next()
      }
    } else {
      if (whiteList.indexOf(to.path) !== -1) {
        next()
      } else {
        next({ path: '/user/login' })
      }
    }
  })
  ```

#### 2.2 按钮级别权限控制
- **实现方式**：通过自定义Vue指令 `v-has` 实现
- **使用方法**：在需要权限控制的按钮上添加 `v-has="permissionCode"` 指令
- **工作原理**：
  1. 指令会检查当前用户是否拥有指定的权限代码
  2. 如果用户没有该权限，指令会将按钮从DOM中移除
  3. 权限检查分为流程节点权限和全局权限两种
- **关键代码**：
  ```javascript
  // hasPermission.js
  Vue.directive('has', {
    inserted: (el, binding, vnode)=>{
      // 节点权限处理，如果命中则不进行全局权限处理
      if(!filterNodePermission(el, binding, vnode)){
        filterGlobalPermission(el, binding, vnode);
      }
    }
  });

  // 全局权限控制
  export function filterGlobalPermission(el, binding, vnode) {
    let permissionList = [];
    let allPermissionList = [];

    // 从sessionStorage获取权限列表
    let authList = JSON.parse(sessionStorage.getItem(USER_AUTH) || "[]");
    for (let auth of authList) {
      if(auth.type != '2') {
        permissionList.push(auth);
      }
    }

    // 检查权限
    if (permissionList === null || permissionList === "" || permissionList === undefined||permissionList.length<=0) {
      el.parentNode.removeChild(el);
      return;
    }
    let permissions = [];
    for (let item of permissionList) {
      if(item.type != '2'){
        permissions.push(item.action);
      }
    }
    if (!permissions.includes(binding.value)) {
      el.parentNode.removeChild(el);
    }
  }
  ```

#### 2.3 权限数据管理
- **存储方式**：权限数据存储在Vuex的permission模块和sessionStorage中
- **数据结构**：
  - 菜单权限：控制用户可访问的页面
  - 按钮权限：控制用户可执行的操作
- **缓存机制**：权限数据在登录时获取并缓存，减少重复请求

### 3. 权限控制流程

1. **用户登录**：输入用户名和密码进行登录
2. **获取权限**：登录成功后，前端向后端请求用户权限列表
3. **生成路由**：根据权限列表动态生成可访问的路由
4. **权限缓存**：将权限数据存储到sessionStorage和Vuex中
5. **页面访问**：路由守卫检查用户是否有权限访问当前页面
6. **按钮显示**：自定义指令检查用户是否有权限看到特定按钮

### 4. 评估结论

jshERP前端确实实现了细粒度的权限控制，精确到每个按钮和菜单。通过路由守卫和自定义指令的结合，实现了完整的权限控制体系：

- **菜单权限**：根据用户权限动态生成可访问的菜单，确保用户只能看到有权限的功能
- **按钮权限**：根据用户权限控制按钮的显示/隐藏，确保用户只能执行有权限的操作
- **路由权限**：未授权的路由无法访问，即使直接输入URL也会被拦截
- **权限缓存**：权限数据缓存，减少重复请求，提高系统性能

这种权限控制机制符合企业级应用的安全要求，能够有效防止未授权访问和操作。

## 5. 前端代码安全问题分析

### 1. 依赖包安全问题

- **Axios版本过旧**：使用的是 ^0.18.0 版本，存在安全漏洞
- **jQuery版本过旧**：使用的是 ^1.12.4 版本，存在安全漏洞
- **CodeMirror版本过旧**：使用的是 ^5.46.0 版本，可能存在安全漏洞
- **其他依赖包**：多个依赖包版本过旧，存在潜在安全风险

### 2. XSS防护问题

- 前端代码中未发现明确的XSS防护措施
- 输入框和富文本编辑器（TinyMCE）可能存在XSS风险
- 缺少内容安全策略（CSP）配置

# 3. CSRF防护问题

- 未发现CSRF token的使用
- 缺少CSRF防护机制

### 4. 敏感信息存储问题

- 权限数据存储在 sessionStorage 中
- 令牌（token）存储在 localStorage 中（通过 Vue.ls）
- 敏感信息未加密存储

### 5. 其他安全问题

- **控制台调试信息**：控制台输出了大量调试信息，可能泄露敏感信息
- **错误处理不完善**：错误处理机制不够完善，可能暴露系统内部信息
- **缺少请求频率限制**：缺少请求频率限制，可能导致DDoS攻击

```javascript
// permission.js 中存在控制台输出
console.log('-----mutations---data----', data);

```

**错误处理不完善代码**：
```javascript

  if (error.response) {
    let data = error.response.data
    // 直接显示错误信息，可能暴露系统内部信息
    notification.error({
      message: '系统提示',
      description: data.message,
      duration: 4
    })
  }
  return Promise.reject(error)

```

### 6. 安全建议

- 更新所有依赖包到最新版本，特别是有安全漏洞的包
- 实现XSS防护措施，如输入验证、输出编码
- 实现CSRF token机制
- 加密存储敏感信息
- 移除控制台调试信息
- 完善错误处理机制
- 实现请求频率限制
